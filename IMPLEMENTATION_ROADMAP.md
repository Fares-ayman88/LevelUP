# Implementation Roadmap — MVP Delivery

## Objective
Turn the current UI into a convincing, approval-ready MVP with a premium Liquid Glass system and fully demoable flows for all core roles.

## Delivery Strategy
Work in 4 focused stages:
1. Stabilize the design system and shared UI foundation.
2. Complete the student and teacher core flows.
3. Complete assistant and center support flows.
4. Polish the experience and prepare it for presentation.

---

## Phase 1 — Foundation (Day 1)
### Goals
- Make the visual system consistent and reusable.
- Ensure the app feels polished from the first screen.

### Tasks
- Finalize the global Liquid Glass token layer in the CSS.
- Standardize reused components: buttons, cards, badges, stat blocks, forms, empty states.
- Ensure light/dark mode works consistently everywhere.
- Improve text contrast on glass surfaces.
- Polish spacing, radius, shadows, and motion.

### Deliverables
- One consistent visual language across the app.
- Shared helpers for cards, actions, pills, and panels.
- Clean theme toggle and preview experience.

---

## Phase 2 — Core Student Experience (Day 2)
### Goals
- Make the student journey clear and compelling.

### Tasks
- Ensure the student home screen shows a clear next step.
- Make explore, booking, payment, attendance, and notifications feel seamless.
- Improve the booking flow with stronger visual hierarchy.
- Improve the attendance experience with a more premium QR + scan state.
- Add polished empty states and success states.

### Deliverables
- Student flow is smooth from landing to action completion.
- Booking experience feels real and convincing.
- Attendance flow feels complete and modern.

---

## Phase 3 — Core Teacher & Assistant Experience (Day 3)
### Goals
- Show that the system supports operational workflows, not just student-facing screens.

### Tasks
- Finish teacher dashboard view with metrics and actions.
- Improve group management and waiting list experience.
- Make attendance session management feel alive and intuitive.
- Show submissions, marks, and follow-up actions.
- Make assistant support view useful and clear.

### Deliverables
- Teacher flow feels operational and product-like.
- Assistant flow supports the staff workflow convincingly.

---

## Phase 4 — Center & Full-System Polish (Day 4)
### Goals
- Make the entire product feel like a cohesive system.

### Tasks
- Complete center dashboard and oversight screens.
- Add consistency across all roles and sections.
- Replace any remaining hard-coded styles with the tokenized visual system.
- Improve responsive behavior for mobile/tablet/desktop.
- Add premium motion and transitions.
- Review copy and hierarchy for clarity.

### Deliverables
- All four roles feel part of the same platform.
- The whole system feels polished and complete.

---

## Phase 5 — Stakeholder Demo Prep (Day 5)
### Goals
- Make the app presentable and easy to demo.

### Tasks
- Prepare a clean flow for each role.
- Ensure the preview route shows a polished snapshot of the system.
- Review the app for visual consistency and confidence.
- Prepare short demo notes for each featured flow.

### Deliverables
- Stakeholder-ready presentation.
- Smooth live demo of the product experience.

---

## Priority Order
1. Shared UI foundation
2. Student core flow
3. Teacher operations flow
4. Assistant and center support flow
5. Visual polish and demo readiness

---

## Launch Checklist
### Product experience
- [ ] All core roles are accessible and understandable
- [ ] Main flows are demoable without confusion
- [ ] Booking, attendance, payments, and communications are visible
- [ ] The UI feels premium and modern

### Design quality
- [ ] Liquid Glass system is applied consistently
- [ ] Theme toggle works everywhere
- [ ] Contrast is readable across cards and surfaces
- [ ] Motion feels smooth and deliberate

### Technical readiness
- [ ] Lint passes cleanly
- [ ] No obvious broken states in the UI
- [ ] Responsive behavior is acceptable across screen sizes
- [ ] Preview page showcases the visual direction clearly

---

## Suggested Next Action
Start with Phase 1 and Phase 2 together: finish the shared visual system and the student booking/attendance flow first, because these are the strongest proof points for stakeholders.
